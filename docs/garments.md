A top and a bottom of the same body fit together, so any top goes with any bottom. "Unisex cut" garments are built once for each body on the same pattern.

## How a garment is stored

Every garment is a folder `garments/<id>/` with:

- `model.glb`, the 3D mesh with the fabric's thickness and UVs,
- `pattern.json`, the print sheet of that garment: its pieces as polygons, their names and default colour roles, and where the front and back are,
- `garment.json`, its name, whether it is a top or a bottom, the body, and its sort order.

`build.rs` finds the folders at compile time and embeds them, so adding a garment needs no Rust change. The format is specified in [blender/GARMENTS.md](../blender/GARMENTS.md).

## How garments are made

The models are generated by Blender scripts, not drawn by hand: `blender/build.py` builds every garment on a posed mannequin, cuts the pieces, unrolls them onto a print sheet and writes the three files. The helpers in `blender/oj/` (body, cuts, legs, sheet layout, previews) are shared; each product has a module in `blender/garments/`.

To rebuild the garments or add one:

1. Download Blender Studio's CC0 *Human Base Meshes* bundle from <https://www.blender.org/download/demo-files/> and unzip it to `assets-src/human-base-meshes/` (this folder is ignored by git).
2. Pose the mannequins:

   ```sh
   for body in man women; do
       blender --background assets-src/human-base-meshes/human-base-meshes-bundle-v1.4.1/human_base_meshes_bundle.blend \
           --python blender/prepare_mannequin.py -- --body $body
   done
   ```
3. Build:

   ```sh
   blender --background --python blender/build.py -- --garment all [--render <dir>]
   ```

   `--garment` also takes one id or an id prefix, and `--render` writes preview images.

Blender's glTF exporter needs numpy; the script adds a user-site install to Blender's path if Blender doesn't bundle one. "Adding a garment" in [blender/GARMENTS.md](../blender/GARMENTS.md) walks through a new product.
